# P2.17 — operator training and acceptance checklist

An operator is ready for a pilot only after a reviewer records each result with the operator ID, date, fixture or command, and outcome.

- [ ] Explain that machine output stops at `watch_candidate`; the operator never treats it as an accusation.
- [ ] Demonstrate `verify_concern` while preserving `watch_candidate`.
- [ ] Demonstrate a refused single-signer whitelist and locate its refusal evidence.
- [ ] Demonstrate two distinct signatures for whitelist, disarm, threshold change, and delete.
- [ ] Explain that refusal evidence is retained and never hidden by error handling.
- [ ] Demonstrate the first broken link returned by index from the verifier.
- [ ] Confirm no raw audio, images, embeddings, or personal data are exported to the public chain.
- [ ] Explain pending versus independently verifiable anchor state.
- [ ] Rehearse escalation, rollback, and the scoped-hotfix procedure.

Acceptance requires every item to pass, a non-operator reviewer’s signature, and a stored synthetic evidence bundle. A checklist with blanks is evidence of training still required, not pilot approval.
